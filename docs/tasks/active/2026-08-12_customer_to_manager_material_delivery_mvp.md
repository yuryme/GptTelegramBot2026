# MVP выдачи методических материалов

- Date: `2026-08-12`
- From: `customer`
- To: `manager`
- Status: `approved`
- Topic: `material_delivery_mvp`
- Goal: `Добавить в текущего Telegram-бота простой сценарий сбора имени и e-mail с отправкой методического файла и синхронизацией заявки с Google Sheets`

## Context

Владелец Instagram-аккаунта публикует предложение получить методические материалы. Ссылка из публикации должна открывать текущего Telegram-бота, который собирает контактные данные, фиксирует согласие на их обработку и отправляет материал на e-mail.

Для первого экземпляра согласован минимальный вариант без Telegram Mini App, отдельной административной панели, объектного хранилища и специализированной платформы рассылок.

## User Flow

1. Пользователь переходит из Instagram по deep link вида `https://t.me/<bot_username>?start=materials_<campaign>`.
2. Бот распознает сценарий выдачи материала и показывает кнопку `Получить файл`.
3. После нажатия бот запрашивает имя.
4. После получения имени бот запрашивает e-mail.
5. Бот проверяет базовый формат e-mail и при ошибке предлагает ввести адрес повторно.
6. Бот показывает имя, замаскированный e-mail, текст согласия и кнопки `Отослать` / `Отмена`.
7. Нажатие `Отослать` фиксирует согласие и создает либо обновляет заявку в PostgreSQL.
8. Сервер отправляет письмо с вложением до 5 МБ через Gmail SMTP.
9. При успешной отправке заявка получает статус `sent`, при ошибке - `failed` с технической причиной в журнале.
10. Данные заявки передаются в Google Sheets через защищенный Google Apps Script webhook.
11. Бот сообщает пользователю об успешной отправке либо о временной ошибке без раскрытия технических деталей.

## Scope

- Расширить текущего Telegram-бота, не создавать отдельного бота.
- Поддержать campaign-метку из Telegram deep link.
- Реализовать отдельный конечный автомат диалога: ожидание имени, e-mail и подтверждения.
- Не отправлять имя и e-mail в LLM.
- Валидировать длину имени и базовый синтаксис e-mail на сервере.
- Хранить заявки в PostgreSQL как в основном источнике данных.
- Фиксировать версию текста согласия и время подтверждения.
- Отправлять один заранее размещенный на VPS файл как MIME-вложение.
- Настраивать путь, отображаемое имя файла, тему и шаблон письма через переменные окружения.
- Отправлять письмо через Gmail SMTP с отдельным App Password.
- Добавлять или обновлять строку в Google Sheets через Apps Script webhook.
- Защитить webhook общим секретом и не передавать секрет в URL.
- Реализовать идемпотентность: повторное нажатие не должно создавать параллельные отправки одного материала на один e-mail.
- Сохранять статусы отправки и синхронизации для диагностики.
- Добавить автоматические тесты и серверный smoke-check.
- Обновить `.env.example`, production env-шаблон и инструкции развертывания при реализации.

## Out Of Scope

- Telegram Mini App и отдельная web-форма.
- Отдельный Telegram-бот.
- Административная web-панель.
- Массовые рекламные рассылки по собранной базе.
- Автоматическая замена материала владельцем через Telegram.
- S3, Google Drive или хранение бинарного файла в PostgreSQL.
- Несколько материалов и визуальный каталог материалов.
- Проверка существования почтового ящика и double opt-in.
- Автоматическое удаление, выгрузка или изменение персональных данных по запросу пользователя.
- SLA, очередь сообщений и полноценная production-инфраструктура электронной почты.

## Data Model

Минимальная таблица `material_deliveries`:

| Field | Purpose |
| --- | --- |
| `id` | Внутренний идентификатор заявки |
| `telegram_user_id` | Идентификатор пользователя Telegram |
| `telegram_username` | Username на момент заявки, если доступен |
| `name` | Имя, введенное пользователем |
| `email` | Нормализованный e-mail |
| `campaign` | Метка Instagram-публикации из deep link |
| `material_code` | Код выдаваемого материала, для MVP один постоянный код |
| `consent_version` | Версия показанного текста согласия |
| `consented_at` | Время явного подтверждения в UTC |
| `delivery_status` | `pending`, `sending`, `sent` или `failed` |
| `delivery_attempts` | Число попыток отправки |
| `sent_at` | Время успешной отправки в UTC |
| `sheet_status` | `pending`, `synced` или `failed` |
| `last_error` | Сокращенная диагностическая ошибка без секретов |
| `created_at`, `updated_at` | Аудит изменения записи |

Ограничение уникальности MVP: `email + material_code`. Повторный запрос не создает новую строку; campaign и пользовательские данные обновляются согласно последней подтвержденной заявке. Повторная отправка уже доставленного материала должна требовать отдельного явного действия пользователя.

## Google Sheet

Google-таблица является представлением данных, а не основным хранилищем. Apps Script принимает JSON по HTTPS и добавляет либо обновляет строку по идентификатору заявки.

Минимальные столбцы:

- ID заявки;
- дата и время заявки;
- имя;
- e-mail;
- Telegram username;
- campaign;
- материал;
- статус отправки;
- дата отправки;
- статус синхронизации.

Сбой Google Sheets не должен отменять уже выполненную отправку письма. Запись остается в PostgreSQL со статусом `sheet_status=failed`, чтобы синхронизацию можно было повторить.

## Configuration

Предполагаемые переменные окружения:

```env
MATERIAL_DELIVERY_ENABLED=false
MATERIAL_FILE_PATH=/opt/telegram-ai-reminder-bot/private/material.pdf
MATERIAL_FILE_NAME=methodical-materials.pdf
MATERIAL_EMAIL_SUBJECT=Ваши методические материалы
MATERIAL_CONSENT_VERSION=2026-08-12

SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=
SMTP_APP_PASSWORD=
SMTP_FROM_EMAIL=
SMTP_FROM_NAME=

GOOGLE_SHEETS_WEBHOOK_URL=
GOOGLE_SHEETS_WEBHOOK_SECRET=
MATERIAL_PRIVACY_CONTACT=
```

Секреты хранятся только в серверном `.env`. Файл материала размещается вручную на VPS вне Git и проверяется при старте либо перед отправкой. Максимальный разрешенный размер вложения для MVP - 5 МБ.

## Privacy And Security

- Перед `Отослать` пользователь должен явно подтвердить сохранение и обработку имени и e-mail для выдачи материала.
- Для закрытого MVP отдельная публичная политика не требуется; текст согласия должен указывать цель обработки и контакт владельца для отзыва согласия и удаления данных.
- Согласованный текст MVP: `Нажимая «Отослать», я соглашаюсь на сохранение и обработку моего имени, e-mail и данных Telegram исключительно для отправки запрошенных методических материалов. Для отзыва согласия и удаления данных: <контакт владельца>.`
- В БД сохраняются `consent_version` и `consented_at`.
- E-mail не выводится полностью в повторных подтверждениях и не записывается в обычные INFO-логи.
- SMTP App Password, webhook URL и webhook secret не попадают в Git, Telegram-сообщения и журналы.
- Команды изменения файла и конфигурации доступны только через SSH администратору VPS.
- Доступ к Google-таблице предоставляет и контролирует ее владелец.
- До открытого публичного запуска Instagram-сценария владелец продукта должен добавить доступную пользователю политику обработки данных и проверить применимые требования для своей юрисдикции.

## Failure Handling

- Неверный e-mail: повторный ввод без потери имени.
- Отмена: очистка состояния диалога без создания подтвержденной заявки.
- Недоступен или превышает лимит файл: отправка не начинается, пользователю показывается временная ошибка.
- Ошибка SMTP: статус `failed`, техническая причина журналируется, пользователь может повторить попытку.
- Таймаут Apps Script: письмо не откатывается, синхронизация помечается как `failed`.
- Повторный Telegram update или двойное нажатие: идемпотентная обработка без двух писем.
- Перезапуск процесса во время диалога: незавершенное состояние может быть потеряно в MVP; подтвержденная заявка и ее статус не теряются.

## Acceptance

- Instagram deep link открывает текущего бота и сохраняет campaign-метку.
- Кнопка `Получить файл` запускает диалог независимо от LLM и состояния DeepSeek.
- Имя и e-mail собираются сообщениями бота; неверный e-mail не принимается.
- Без нажатия `Отослать` согласие и отправка не фиксируются.
- После подтверждения в PostgreSQL появляется запись с версией согласия и временной меткой.
- Тестовое письмо с вложением до 5 МБ приходит на Gmail и как минимум один внешний почтовый домен.
- Успешная заявка появляется в Google Sheets с campaign и статусом доставки.
- Недоступность Google Sheets не мешает отправке письма и отражается в БД.
- Двойное нажатие `Отослать` не вызывает двойную отправку.
- Имя, полный e-mail и секреты отсутствуют в штатных INFO-логах.
- Тесты покрывают успешный сценарий, невалидный e-mail, отсутствие согласия, SMTP-ошибку, Sheets-ошибку и повторный запрос.
- После деплоя выполнен Telegram smoke-test и проверены журналы сервиса.

## Operating Cost Estimate

- Текущий VPS и PostgreSQL: без дополнительной стоимости, если хватает существующих ресурсов.
- Gmail SMTP: без отдельной платы в пределах лимитов аккаунта; это технический компромисс MVP, а не гарантированный канал массовой доставки.
- Google Sheets и Apps Script: обычно без отдельной платы при согласованном объеме до 300 заявок в месяц, с учетом квот Google-аккаунта.
- Доменная почта и специализированный транзакционный сервис не входят в MVP.

## MVP Limits And Upgrade Triggers

- Gmail может ограничивать суточную отправку, блокировать подозрительную активность и не предоставляет полноценный SLA доставки.
- Вложение увеличивает размер письма и повышает риск попадания в спам; предел MVP установлен в 5 МБ.
- Apps Script имеет квоты и не заменяет очередь надежной доставки.
- При росте выше 300 отправок в месяц, жалобах на недоставку или появлении нескольких материалов следует перейти на транзакционный почтовый сервис, ссылочную доставку из объектного хранилища и фоновую очередь задач.
